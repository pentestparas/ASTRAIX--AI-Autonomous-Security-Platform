# AI Agent Cybersecurity - incident_response_playbooks

- playbook_id: IRP-001 | attack_type: Prompt Injection | trigger_indicators: Agent performs unexpected actions; System prompt leaked in output; Agent ignores original task | immediate_steps: 1. Terminate current agent session
2. Rotate API keys if agent had tool access
3. Review agent action logs for unauthorized operations
4. Assess if any tools were triggered inappropriately | short_term_mitigation: Deploy input sanitization; Add Prompt Shield or NeMo Guardrails; Implement output filtering before action execution | long_term_remediation: Red-team test all input vectors; Fine-tune model on adversarial examples; Implement privilege separation between reading and acting | affected_components: LLM System Prompt, Agent Tool Executor | escalation_criteria: If agent executed file writes, API calls, or sent emails → escalate to security team | recovery_time_estimate: 2–4 hours | severity: Critical | source: OWASP LLM01 Incident Guide
- playbook_id: IRP-002 | attack_type: Indirect Prompt Injection | trigger_indicators: Agent behavior changes after reading external content; Unexpected outbound requests from agent; Agent returns content unrelated to user query | immediate_steps: 1. Disconnect agent from external data sources
2. Preserve logs of web pages/documents accessed
3. Check if any data was exfiltrated via tool calls
4. Quarantine affected agent session | short_term_mitigation: Treat all external content as untrusted; Add content trust scoring; Sandbox web browsing tool | long_term_remediation: Implement separate LLM to sanitize external content before main agent sees it; Deploy agent behavior monitoring | affected_components: Agent Tool: Web Browser, Email Reader, Document Loader | escalation_criteria: If sensitive data was sent to external URL → immediate security incident | recovery_time_estimate: 4–8 hours | severity: Critical | source: Greshake et al. / MITRE ATLAS AML.T0051.001
- playbook_id: IRP-003 | attack_type: Tool Poisoning / MCP Attack | trigger_indicators: Unknown tool registered in agent; Tool returning unexpected data; Agent making calls to unrecognized endpoints | immediate_steps: 1. Immediately disable all unrecognized tools
2. Audit tool registry for unauthorized additions
3. Check tool call logs for data exfiltration patterns
4. Revoke tool API credentials | short_term_mitigation: Implement tool allowlist; Verify cryptographic signatures on MCP servers; Block all outbound tool calls until audited | long_term_remediation: Deploy MCP server registry with verified publishers; Implement tool call rate limiting and monitoring | affected_components: Agent Tool Registry, MCP Server | escalation_criteria: If tool sent sensitive data externally → data breach protocol | recovery_time_estimate: 2–6 hours | severity: Critical | source: Invariant Labs MCP Security Guidelines 2025
- playbook_id: IRP-004 | attack_type: Memory Poisoning | trigger_indicators: Agent behavior changed across sessions; Agent references events or facts that never occurred; Persistent incorrect agent behavior | immediate_steps: 1. Immediately wipe agent memory store
2. Inspect memory contents for injected records before deletion
3. Identify the session in which poisoning occurred
4. Rebuild memory from verified clean sources | short_term_mitigation: Enable memory content validation; Require human approval for new memory writes; Implement memory versioning with rollback | long_term_remediation: Add anomaly detection on memory writes; Implement memory content signing; Regular memory audits | affected_components: Vector Database (ChromaDB, Pinecone), Agent Long-Term Memory | escalation_criteria: If memory contained attacker-controlled instructions executed across sessions → full audit required | recovery_time_estimate: 6–24 hours (memory rebuild time) | severity: High | source: OWASP LLM03 / AutoGPT Security Guidelines
- playbook_id: IRP-005 | attack_type: RAG Poisoning | trigger_indicators: Agent citing non-existent sources; Agent providing incorrect or harmful information confidently; RAG responses misaligned with known facts | immediate_steps: 1. Quarantine RAG knowledge base
2. Identify and remove injected documents
3. Trace document ingestion logs to find attack vector
4. Temporarily disable RAG and use base model | short_term_mitigation: Implement document source authentication; Add retrieval output filtering; Cross-validate RAG responses with trusted sources | long_term_remediation: Immutable document store with versioning; Document provenance tracking; Regular knowledge base integrity audits | affected_components: RAG Vector Store, Document Index | escalation_criteria: If attacker-injected documents contained malicious instructions executed by agent → critical incident | recovery_time_estimate: 4–12 hours | severity: High | source: NVIDIA AI Red Team Best Practices
- playbook_id: IRP-006 | attack_type: Agent Hijacking / Worm | trigger_indicators: Agent spawning unexpected sub-agents; Unusual resource consumption; Agent acting outside defined task scope | immediate_steps: 1. Emergency shutdown of all agent instances
2. Isolate affected systems from network
3. Preserve forensic evidence of agent actions
4. Audit all actions taken by rogue agents | short_term_mitigation: Disable agent self-replication capability; Implement human approval for sub-agent spawning; Rate limit agent instance creation | long_term_remediation: Implement agent identity certificates; Deploy agent behavior monitoring with kill-switch; Principle of least agent privilege | affected_components: Agent Runtime, Agent Spawning System, Network | escalation_criteria: If rogue agents spread to external systems → immediate incident response + regulatory notification | recovery_time_estimate: 8–48 hours | severity: Critical | source: ComPromptMized Worm Research / MITRE ATLAS AML.T0048
- playbook_id: IRP-007 | attack_type: Model Supply Chain Attack | trigger_indicators: Unexpected model behavior on specific trigger inputs; Model returning harmful content not consistent with safety training; Unusual model output patterns | immediate_steps: 1. Immediately remove suspicious model from production
2. Scan model file with Protect AI ModelScan
3. Verify model hash against official source
4. Roll back to previous verified model version | short_term_mitigation: Only load models from verified, hash-checked sources; Use safetensors format (no pickle execution risk); Implement model behavior test suite | long_term_remediation: Establish model provenance policy; Regular model behavioral audits; Automated model scanning in CI/CD pipeline | affected_components: LLM Model Weights, Model Loading Pipeline | escalation_criteria: If backdoored model was in production → audit all outputs since deployment; potential data breach | recovery_time_estimate: 2–4 hours (rollback) + weeks (full audit) | severity: Critical | source: Protect AI ModelScan / MITRE ATLAS AML.T0018
- playbook_id: IRP-008 | attack_type: Training Data / RAG Extraction (Data Leak) | trigger_indicators: Agent outputting PII in responses; Model regurgitating verbatim training data; Responses containing private customer information | immediate_steps: 1. Enable emergency output filtering for PII
2. Log all affected queries for legal review
3. Identify which training data/RAG source is being leaked
4. Notify affected data subjects if PII leaked (GDPR/CCPA) | short_term_mitigation: Deploy PII detection on all LLM outputs; Add differential privacy to inference; Implement output scrubbing | long_term_remediation: Re-train model with differential privacy (DP-SGD); Purge sensitive data from training set; Implement membership inference monitoring | affected_components: LLM Training Data, RAG Knowledge Base | escalation_criteria: Any PII exposure → mandatory regulatory notification (GDPR 72hr, CCPA); engage legal team | recovery_time_estimate: Immediate (filtering) + months (retraining) | severity: High | source: OWASP LLM02 / GDPR Incident Response
- playbook_id: IRP-009 | attack_type: Jailbreak / Guardrail Bypass | trigger_indicators: Agent producing harmful content (CBRN info, illegal instructions); Model abandoning safety persona; Unusual response patterns | immediate_steps: 1. Block offending input pattern immediately
2. Log and preserve jailbreak prompt for analysis
3. Check if harmful content was shown to end users
4. Assess content policy violation scope | short_term_mitigation: Update safety classifier with new jailbreak pattern; Deploy output content moderation layer; Increase monitoring sensitivity | long_term_remediation: Include new jailbreak patterns in adversarial training; Red-team test with new variant; Update RLHF dataset | affected_components: LLM Safety Guardrails, Output Filter | escalation_criteria: If harmful content involving minors or CBRN was generated and shown to users → legal/regulatory notification | recovery_time_estimate: Hours (patching) + weeks (retraining) | severity: High | source: OWASP LLM01 / Anthropic Usage Policy
- playbook_id: IRP-010 | attack_type: Multi-Agent Orchestrator Compromise | trigger_indicators: Orchestrator delegating tasks outside normal scope; Sub-agents receiving unusual instructions; Unexpected inter-agent communication patterns | immediate_steps: 1. Shutdown orchestrator and all active sub-agents
2. Audit all task delegations from the last 24 hours
3. Identify the compromised agent in the pipeline
4. Review all actions taken on behalf of orchestrator | short_term_mitigation: Implement agent identity verification between agents; Add human approval for cross-agent sensitive task delegation; Deploy inter-agent message filtering | long_term_remediation: PKI-based agent authentication; Anomaly detection on orchestrator decisions; Redesign pipeline with zero-trust agent architecture | affected_components: Multi-Agent Orchestrator, Inter-Agent Communication | escalation_criteria: If sub-agents took real-world actions (emails sent, files deleted, APIs called) → full audit + stakeholder notification | recovery_time_estimate: 4–24 hours | severity: Critical | source: CrewAI Security Guidelines / MITRE ATLAS AML.T0048
- playbook_id: IRP-011 | attack_type: Autonomous Vehicle Sensor Attack | trigger_indicators: Sudden unexpected braking or acceleration; Lane departure without cause; Navigation routing to unexpected destination | immediate_steps: 1. Immediately switch to manual control
2. Pull over safely and stop vehicle
3. Disable all autonomous driving features
4. Preserve sensor logs and camera footage | short_term_mitigation: Enable cross-sensor validation mode; Increase anomaly detection sensitivity; Disable V2X reception until verified | long_term_remediation: Deploy multi-sensor fusion with attack detection; Update sensor firmware; Implement GPS signal authentication (OSNMA) | affected_components: LiDAR, Camera, GPS, Radar Sensors | escalation_criteria: If attack caused accident or injury → emergency services + manufacturer incident report | recovery_time_estimate: Vehicle service required — days | severity: Critical | source: AutoSec Workshop / NHTSA Cybersecurity Guidelines
- playbook_id: IRP-012 | attack_type: CAN Bus / In-Vehicle Network Attack | trigger_indicators: Unexpected ECU behavior; Brake or steering responding abnormally; OBD-II anomalous read attempts | immediate_steps: 1. Disconnect OBD-II port immediately
2. Switch to manual control
3. Have vehicle towed to authorized service center
4. Preserve CAN bus logs | short_term_mitigation: Enable CAN bus anomaly detection (IDS); Block unauthorized OBD-II access; Update ECU firmware | long_term_remediation: Implement CANsec encryption; ECU authentication; Network segmentation between infotainment and safety ECUs | affected_components: CAN Bus, ECUs (brake, steering, acceleration) | escalation_criteria: Any confirmed CAN injection → vehicle recall consideration + manufacturer report | recovery_time_estimate: Service required — days to weeks | severity: Critical | source: Miller & Valasek / NHTSA / SAE J3061
- playbook_id: IRP-013 | attack_type: LLM-Controlled Robot Hijacking | trigger_indicators: Robot performing movements not commanded by user; LLM copilot ignoring safety zones; Unexpected robot speed or force | immediate_steps: 1. Press physical emergency stop immediately
2. Disconnect robot from LLM interface
3. Return robot to safe home position
4. Preserve all LLM conversation logs | short_term_mitigation: Implement mandatory human confirmation for all physical movements; Deploy separate safety controller independent of LLM; Add physical workspace monitoring | long_term_remediation: Separate LLM from safety-critical control loop entirely; Implement formal safety verification; Red-team LLM-robot interface | affected_components: LLM Natural Language Interface, Robot Controller | escalation_criteria: If humans were near robot during incident → immediate safety investigation + regulatory report | recovery_time_estimate: Hours (investigation) + weeks (safety review) | severity: Critical | source: CMU/Brown LLM Robot Safety Research arXiv:2402.11208
- playbook_id: IRP-014 | attack_type: MCP Package Supply Chain Attack | trigger_indicators: MCP server sending unexpected network traffic; Tool call data appearing on external servers; Unexpected MCP server behavior after update | immediate_steps: 1. Immediately uninstall suspected MCP package
2. Revoke all API keys that MCP server had access to
3. Audit all tool calls made since package installation
4. Check for data exfiltration in network logs | short_term_mitigation: Block all outbound traffic from MCP servers pending audit; Only reinstall MCP from official verified registry | long_term_remediation: Implement MCP server dependency scanning in deployment pipeline; Use package hash pinning; Deploy network egress monitoring for MCP processes | affected_components: MCP Server Package, Tool Registry | escalation_criteria: If customer data was exfiltrated → breach notification protocol | recovery_time_estimate: 2–8 hours (remediation) + investigation time | severity: Critical | source: Socket.dev / Invariant Labs 2025
- playbook_id: IRP-015 | attack_type: Denial of Service (Prompt Bomb) | trigger_indicators: LLM API timeout rates increasing; Token usage spiking abnormally; Per-user cost spikes; Legitimate users unable to access agent | immediate_steps: 1. Enable emergency rate limiting per IP/user
2. Block requests exceeding token limit threshold
3. Scale up compute if budget allows
4. Identify and block attacking IP ranges | short_term_mitigation: Implement request queuing; Set hard token limits per request; Add CAPTCHA for suspicious traffic patterns | long_term_remediation: Implement complexity scoring on inputs; Deploy request authentication; Monitor for adversarial prompt patterns | affected_components: LLM API Compute, Rate Limiter | escalation_criteria: If attack sustained > 1 hour causing full service outage → DDoS mitigation service + provider notification | recovery_time_estimate: 1–4 hours | severity: High | source: OWASP LLM04 / Shumailov et al.
